# Python version floor/ceiling for this requirements file.
#
# The images are built `FROM python:3.10-slim`, and Dependabot has no other way
# to know that: a requirements.txt carries no `python_requires`, so it happily
# proposes releases that cannot install here. It did exactly that on 2026-08-27
# -- scipy 1.18.1 (needs >=3.12), scikit-image 0.26.0 and matplotlib 3.11.1 --
# and the ML build died at `pip wheel` with "No matching distribution found".
#
# With this file present Dependabot resolves against 3.10 and stops proposing
# the impossible. If the base image moves, move this with it.
#
# numpy is a second, independent ceiling and .python-version cannot express
# it. numpy is pinned at 1.26.4 because that is what the pinned torch 2.6.0
# was built against, and torch cannot move while mamba-ssm and causal-conv1d
# ship CUDA kernels compiled against it. So anything requiring numpy>=2 is
# out regardless of Python: opencv-python-headless stops at 4.11.0.86 here,
# not the 4.14 Dependabot offered, and pip fails the build outright rather
# than resolving around it. Check `requires_dist` for a numpy bound before
# raising any of the numeric pins below.

# Microtubule v7 standalone inference — pinned to the versions the
# cell-segmentation-hub ML service runs in production (Python 3.10).
# All have macOS arm64 (Apple Silicon) wheels, so this installs on a MacBook.
#
#   python3 -m venv .venv && source .venv/bin/activate
#   pip install -r requirements.txt
#
# torch is LOAD-BEARING and pinned at 2.6.0: mamba-ssm and causal-conv1d ship
# CUDA kernels source-built against it, so moving torch means recompiling both
# and re-pairing torchvision.
#
# transformers is NOT used by this worker at all any more. The old 4.57.1 pin
# was for the microtubule v7 DINOv3 backbone, where 4.57.2 silently degraded the
# ViT features. v5H (2026-08-17) replaced v7 with an nnU-Net whose checkpoint
# carries every weight, so the MT path imports no transformers and needs no
# HF_TOKEN. The pin is kept only to stay identical to the ml image this worker is
# built FROM, so the two can never resolve different versions of a shared stack.
# It tracks backend/segmentation/requirements.txt -- change both together, and
# read the CEILING note there before crossing a transformers minor.

# --- Deep learning core ---
torch==2.6.0
torchvision==0.21.0
transformers==5.5.4
huggingface_hub>=1.29.0

# --- Numerics / classical CV (PySOAX postprocessing) ---
numpy==1.26.4
